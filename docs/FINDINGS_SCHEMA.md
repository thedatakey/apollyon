# Findings output contract

`apollyon scan <path> --format json` emits one compact JSON object on stdout,
unless `--output <file>` is supplied. Consumers must inspect both the exit code
and `summary.complete`. Findings are bounded review candidates or taint evidence,
never a whole-program security verdict.

## `apollyon.findings/v2`

```json
{
  "schema": "apollyon.findings/v2",
  "tool": { "name": "apollyon", "version": "0.2.0" },
  "scope": "Findings reflect a fixed set of bounded lexical rules only. Zero findings is not a security guarantee and does not imply the scanned code is safe.",
  "root": "project",
  "summary": {
    "supported_files": 1,
    "scanned_files": 1,
    "skipped_files": 0,
    "skipped_symlinks": 0,
    "excluded_files": 0,
    "excluded_directories": 0,
    "total_bytes": 82,
    "suppressed_errors": 0,
    "complete": true,
    "suppressed_findings": 0,
    "disabled_findings": 0,
    "new": 1,
    "baselined": 0,
    "total": 1,
    "unselected_files": 0,
    "missing_selected_files": 0,
    "unsupported_selected_files": 0,
    "ast_files": 1,
    "lexical_files": 0,
    "parse_fallback_files": 0
  },
  "errors": [],
  "findings": [{
    "rule_id": "APO004",
    "severity": "high",
    "message": "Dynamic code execution requires review...",
    "engine": "ast",
    "confidence": "tainted",
    "trace": [
      {"path":"app.py","line":2,"kind":"source"},
      {"path":"app.py","line":3,"kind":"sink"}
    ],
    "fingerprint": "64-lowercase-hex-characters",
    "path": "app.py",
    "line": 3,
    "snippet": null
  }]
}
```

The fixed `scope` wording still refers to lexical rules because tree-sitter
validates candidates generated by that bounded registry; taint raises confidence
only for modeled source-to-sink flows.

- `root` is a privacy-preserving label. Finding and trace paths are slash-normalized
  and relative to it.
- `engine` is `ast` when tree-sitter parsed the file and validated the relevant
  expression/call, otherwise `lexical` after explicit fallback.
- `confidence` is `candidate` or `tainted`. `tainted` means a modeled source
  reached this sink within the recorded scope without a modeled sanitizer.
  It does not mean confirmed exploitability.
- `trace` is empty for candidates; tainted findings contain ordered `source`,
  optional `propagation`/`call`, and `sink` steps, capped at ten.
- `fingerprint` is stable across unrelated line insertions; see [CONFIG.md](CONFIG.md).
- `snippet` is null unless requested and is always null for secret-candidate lines.
- `ast_files`, `lexical_files`, and `parse_fallback_files` expose engine coverage.
  Syntax errors, parser timeouts, grammar mismatch, more than 1,000,000 AST
  nodes, or more than 16 MiB of repeated inspected-node text trigger lexical
  fallback. The 2 MiB source-file bound still applies.
- `total = new + baselined + suppressed_findings + disabled_findings`.
- Selection and exclusion fields must be inspected when interpreting coverage.
- Decoding, traversal, lexical-state, resource, and limit failures make
  `complete` false and produce exit 3. Parser fallback alone is a supported
  degraded mode and remains explicitly counted.

## SARIF

SARIF remains version 2.1.0. Results include `properties.engine`,
`properties.confidence`, and `properties.trace`, plus the stable fingerprint in
`partialFingerprints["apollyon/v1"]`. Invocation properties contain scan,
selection, filter, and parser coverage. Tool notifications contain incomplete
scan errors. Snippets remain opt-in.

## Difference from `apollyon.findings/v1`

V2 retains the v1 root, tool, scope, coverage, error, rule, severity, message,
path, line, snippet, fingerprint, and adoption-control meanings. It requires
`engine`, `confidence`, and `trace`, and adds parser coverage counters. Consumers
that require v1 must reject the v2 discriminator instead of assuming absent
fields. Baseline files remain `apollyon.baseline/v1`; finding fingerprints did
not change when the analysis engine was added.

The historical v1 contract had no engine/confidence/trace fields. Its original
findings had only rule/severity/message/path/line/snippet; Phase 1 additively
introduced fingerprint and adoption counters while retaining the v1 discriminator.
